Start here: Copilot Chat (Basic)What this guide uses, how to sign in, and how to practice safely.

Basic only

This guide uses standalone Microsoft Copilot Chat (Basic): an eligible Microsoft 365 work account without a Microsoft 365 Copilot add-on. Open Microsoft Copilot Chat, sign in with your work account, and confirm the work-data protection indicator is visible.

No paid Copilot add-on or app integration

▼

Every exercise runs in standalone chat using fictional text you paste. Each practice source also has an Open button for a TXT, CSV, PDF, or HTML file version of the same text. Nothing needs Copilot in Word, Excel, Outlook, or Teams, work-data search, or agents. Web search may be off in your organization; if so, use the pasted excerpts.

How to practice safely

▼

Use one chat thread: paste each practice block, then its prompts. Contoso Bottling Company and its people and figures are fictional. For real work, never enter passwords or prohibited data, and review every result before acting.

Suggested 90 minutes: 8 for access, 7 for prompting, 55 for exercises, 15 for questions, 5 for wrap-up.

FICTIONAL FORMULA AND TRAINING POLICY
My name is Avery Patel. Column D is the due date, column F is the open amount, and B1 is the reporting date.
Apply the fictional training policy in this order: If F is blank or nonnumeric, return Check amount. Otherwise, if F is negative, return Credit; if F is zero, return Zero balance. For positive amounts only, if the due date in D or reporting date in B1 is missing or invalid, return Check date. Otherwise, calculate calendar days overdue using date-only values: 0 or fewer days is Current; 1-30 days is 1-30; 31-60 days is 31-60; 61-90 days is 61-90; 91 or more days is 91+.
For this exercise, amounts must be numeric values, not numeric-looking text. Assume Excel uses its 1900 date system. Accept date-only values from 01/01/2000 through 12/31/9999, inclusive: whole-number numeric date serials in Excel and date-typed values in Power Query. Treat text dates and dates outside that range as invalid rather than guessing or converting them.
Legacy formula:
=IF(F2<=0,"Credit",IF(D2="","Check",IF($B$1-D2<=0,"Current",IF($B$1-D2<=30,"1-30",IF($B$1-D2<=60,"31-60",IF($B$1-D2<90,"61-90","90+"))))))
Starting prompt (GCSE)▼
Starting prompt - Goal, Context, Source, Expectation
What this prompt doesSeparates a legacy formula from the rule it is supposed to implement.
Did you know? A useful formula review needs explicit business rules as well as code.
Goal: Explain the legacy aging formula, identify logic problems, and propose a maintainable correction.
Context: I am Avery, a fictional GBS analyst. A new teammate needs to understand and safely test this formula.
Source: Use only the formula and fictional training policy I just pasted. Do not assume a real organization's accounting policy.
Expectation: Provide a step-by-step explanation, identify the day-90 and zero-balance issues, and propose a LET/IFS formula. Show test cases for days 0, 30, 60, 90, and 91; a blank or numeric-looking text amount; a positive amount with a missing, text, or out-of-range date; and negative and zero amounts with missing dates. Flag anything not supported by the source.
Follow-ups (2)▼

Rewrite the corrected logic using a small settings table and an approximate-match lookup. Show the table, and explain how invalid amounts, negative or zero amounts, and missing or invalid dates are handled in the policy's stated order before the lookup.
What this prompt doesTranslates the rule into a repeatable transformation and checks edge cases.

Copilot tips & tricksPractical habits plus quick links to every exercise.

Quick reference

Expand a technique, then apply it to the fictional exercises.

Ask for questions before answers▼

For an unclear request, have Copilot ask for missing requirements before it drafts. Give the answers in the same conversation so the final result uses them.

Define what brief means▼

Name a maximum length and output shape: six lines, three bullets, or a table with specified columns. Words such as quick and concise leave room for interpretation.

Change one thing in a follow-up▼

Ask for a different format, audience, tone, or level of detail one change at a time. Review whether the factual content stayed grounded after each revision.

Separate facts, assumptions, and unknowns▼

Require visible labels for unsupported claims and missing inputs. A plausible explanation is not proof; a suggested owner is not an assigned owner.

Challenge the answer with evidence▼

Ask which claims are directly supported and which are not. Compare its evidence against the actual source rather than relying on Copilot's own confidence.

Recalculate important numbers▼

Ask to see intermediate calculations, then independently check important totals and thresholds. AI output does not approve a payment, record change, or accounting entry.

Keep the thread, fence the source▼

Use the same conversation for related follow-ups. When changing exercises, paste the new practice source and make the allowed source explicit so earlier examples do not leak into the new task.

Review before saving or sharing▼

Check recipients, sensitive content, source accuracy, and your organization's rules before using an output. Save only safe, durable preferences or recurring work instructions, not case-specific data.
