    Demo 01

    Choose the right tool for this taskDecide when a prompt, skill, agent, or Researcher fits.

    Microsoft 365 Copilot
    A. Paste the practice source▼

    Open Microsoft 365 Copilot Chat with your ELC work account. Start a new chat, copy the backlog below, paste it, and send it. After the acknowledgment, use the starting prompt in B in the same chat.

    Expected acknowledgmentAfter you paste the source, Copilot should reply only: “Got it. I'll use this as the source.”
    Paste this first - practice source
    Open TXT
    GCCS REQUEST BACKLOG
Persona: Jordan Lee, consumer insights researcher.
Practice date: Monday, November 16, 2026.
Team: GCCS Research, Project Aurora (Aurora Skin Comfort Study).
Team personas: Taylor Brooks (knowledge owner), Jordan Lee (Research), Priya Shah (Analytics), Morgan Chen (Operations).
Definitions:
- Prompt: a one-time request in Copilot Chat or an app.
- Skill: reusable instructions for one repeatable task. Select it when needed; automatic use is optional and should be tested.
- Agent: a dedicated assistant with its own instructions, knowledge sources, and starter prompts, built in Agent Builder.
- Researcher: a built-in agent for complex, multistep research that returns a source-cited report.
- Keep human authority: approvals and decisions stay with responsible people.
Requests:
R1. Every Monday, turn the latest fieldwork snapshot into a five-line status brief in the same format.
R2. Summarize one transcript from the October 30, 2026 protocol checkpoint.
R3. Give GCCS researchers one place to ask questions about approved protocols, templates, and data dictionaries.
R4. Compare published evidence on skin-comfort self-report scales with approved protocol context, and give me a cited report before the decision on November 18, 2026.
R5. Approve the consumer-facing comfort claim for the Aurora readout.
R6. Check participant-facing message drafts against the approved plain-language checklist and reading-level rule.
R7. Rename the columns in one spreadsheet I am cleaning today.
After you receive this source, reply only: "Got it. I'll use this as the source."
    B. Starting prompt (GCSE)▼
    Starting prompt - Goal, Context, Source, Expectation
    What this prompt doesSorts requests into one-time prompts, reusable skills, shared agents, Researcher work, and decisions that must stay with people.
    Goal: Classify each request as a prompt, skill, agent, Researcher, or do not automate.
Context: My GCCS team wants to stop retyping instructions and choose the right tool for each request.
Source: Use only the request backlog and definitions I pasted.
Expectation: A table with the request, classification, one-sentence reason, and stated frequency; then recommend one skill and one agent to build first.
    C. Follow-ups (2)▼
    Follow-ups - same thread
    What this prompt doesChecks whether the classification depends on missing information.
    Which request needs a clarifying question before I could design the workflow? Ask any clarifying questions before responding.
    What this prompt doesKeeps human authority visible.
    Which request must remain with a person, and why? Do not propose a skill or agent that approves the claim.
    D. What to check▼
    • R1 and R6: recurring, rule-based work; a skill fits.
    • R2 and R7: one-time tasks; a prompt is enough.
    • R3: a shared destination for approved library questions; an agent fits.
    • R4: multistep, cited research; Researcher fits.
    • R5: claim approval stays with the responsible person.
    • Do not invent frequency for R3 or R4.
    E. Tip: Ask before assuming▼
    When audience, scope, source, or decision context could change the result, ask clarifying questions before proceeding. That can reduce assumptions and rework, but it does not replace source checks or human review.
    F. Did you know? Skills and agents solve different problems▼
    A skill is a reusable workflow for a repeatable task. An agent is a dedicated assistant with its own instructions, knowledge sources, and starter prompts. Researcher is designed for multistep research that returns a source-cited report. Microsoft Support: Create and edit skills · Microsoft Learn: Build agents with Agent Builder

    Agent Builder
    A. Describe the agent (GCSE)▼
    1. In your browser, open m365.cloud.microsoft and sign in with your ELC work account.
    2. Select Agents & Skills > New agent. Depending on rollout, the labels may be Agents and Create agent.

    Describe request - practice input
    Open TXT
    DESCRIBE INPUT - AURORA LIBRARY GUIDE
Use this as the Describe request in Agent Builder. It is an agent-configuration prompt, not a knowledge source.
Goal: Create a personal agent for finding and understanding approved Project Aurora research materials.
Context: I'm Taylor Brooks, Research Knowledge Manager. About 80 GCCS researchers, all with Microsoft 365 Copilot licenses, need a reliable way to find approved materials.
Source: Use the requirements below. Do not assume a SharePoint folder or library is connected.
Expectation: Create the named agent with the description, instructions, and starter prompts below. Do not configure sharing.
Name: Aurora Library Guide
Description: Helps GCCS researchers find approved Aurora materials. Cite the uploaded evidence file and identify the original source name and approval date.
Instructions:
- Answer only from knowledge sources I add in Agent Builder. Do not assume a SharePoint folder or library is connected.
- Cite the uploaded file d03-approved-library-knowledge.txt for material facts, and state the original source name and approval or snapshot date shown in that file. Do not imply that the original DOCX/XLSX files are attached.
- Identify whether a source is a protocol, data dictionary, template, checklist, or fieldwork snapshot.
- Use the current approved protocol when reporting the target sample. Do not use archive drafts.
- A template is not evidence of study results. Do not infer results, effects, or claims.
- Do not reveal participant names, IDs, or row-level information.
- Do not approve claims, studies, protocols, or communications. Keep decisions with the responsible reviewer.
- If the knowledge sources do not contain the answer, say so plainly and suggest asking Taylor Brooks.
- Keep answers brief, professional, and in US English. Use dates such as November 16, 2026.
- Do not send messages, publish, change files, or take external actions.
Starter prompts:
- Where is the current Aurora data dictionary? Cite its file and date.
- What is the approved target sample? Cite the current protocol.
- Is there an approved final result for this question?
    B. Review the same agent in Configure▼

    Open Configure. Confirm the name is Aurora Library Guide, the description says it cites source files and approval dates, and the instructions preserve the source, privacy, and human-decision boundaries. Check the starter prompts. Correct any field that Describe did not populate as requested.

    Agent Builder field limits are 30 characters for the name, 1,000 for the description, and 8,000 for instructions. Try it becomes available when the required fields are present. Do not create the agent yet; add knowledge and test it first.

    C. Refine the agent instructions▼

    Return to Describe, paste the refinement below in Message Agent Builder, and send it. Wait, then return to Configure to check that the instructions changed.

    Follow-up in Agent Builder
    What this prompt doesImproves the same agent configuration without changing its role.

Put the data privacy and human-approval boundaries first, then require a citation to the uploaded evidence file and the original source name and approval or snapshot date for each material fact. Do not add a SharePoint connection or any external action.
    D. What to check▼

    • The description fits the 1,000-character limit and explains when the agent is useful.
    • Instructions fit the 8,000-character limit and prohibit participant-level inference, claim approval, and external actions.

    • This is the one Aurora Library Guide agent that continues through Knowledge and Try it.

    C. Check readiness and source citations▼

    D. What to check▼

    Before you use skills in OfficeCheck access once before Demo 05.

    Office prerequisites
    • License and access: everyone in this class has a Microsoft 365 Copilot license. Your organization must also enable Copilot and custom skills. If the Copilot button is missing in Word, PowerPoint, or Excel, tell the instructor and follow along.
    • Same account: sign in to all three apps with your ELC work account. Check the name or profile icon at the top right.
    • Updated desktop apps: use Microsoft 365 Word, PowerPoint, and Excel for Windows or Mac. On Windows, choose File > Account > Update Options > Update Now; on Mac, choose Help > Check for Updates. If your organization manages updates, ask the instructor for help. Skill menus may be missing or different in web apps. The PowerPoint skills article lists Microsoft 365 for Windows, Mac, and iPad; this guide uses desktop steps, with Windows labels shown.
    • Work OneDrive: custom skills are saved in a Skills folder in your OneDrive. Make sure your work OneDrive opens. Save each practice file using File > Save As > OneDrive. Keep AutoSave On when available; this is recommended for reliable Copilot editing, not a strict requirement.
    • Availability: skills roll out gradually and are controlled by your organization. Labels can say skills, plugins, or plugins and skills. The Word-specific labels below were observed in the desktop app; the general support article does not document those exact Word labels.
    • Create once: Demo 05 saves aurora-status-brief. Use this exact name (lowercase letters, numbers, and hyphens; up to 64 characters). The description can contain up to 1,024 characters. Do not create duplicates; try Refresh if the saved skill is missing.
    • On/off differences: in PowerPoint, a skill turned off in Manage skills is hidden from the skill menu. In Excel, a turned-off skill can still be selected by typing its name after @. For these demos, keep the skill turned on and select it from the menu.
    • Protect data: keep confidential information, participant data, passwords, and secrets out of skills. Use only this guide's practice files.

    What you need to know

    Only how to open a blank file, click the guide's Copy button, paste with Ctrl+V (Windows) or Cmd+V (Mac), click Home > Copilot, and save to OneDrive. A pane is the panel that opens at the side of the app; a worksheet is a tab inside an Excel workbook. The demos walk through the remaining steps.

    Where to click

    Start with Home > Copilot in each app. The ... button is More options/Settings in the Copilot pane. A + is a button, not something to type.

    AppChoose the saved skillRefresh the list
    Word+ (labeled Add sources, skills, and more) > Choose plugins; choose the skill in the Plugins list.... > Manage plugins > Custom skills > Refresh
    PowerPoint+ > Choose skills... > Manage skills > Refresh (open Custom skills if shown)
    ExcelAdd > Choose plugins and skills... > Manage plugins & skills > Custom skills > Refresh

Goal: Create or update a concise Aurora fieldwork status brief.
Context: The same repeatable brief is used in Word, PowerPoint, and Excel.

Create a concise five-line brief with these labels:
- As of
- Enrollment
- Completion
- Withdrawals
- Open items

Use the snapshot date and counts exactly as shown in the active file. When the approved target is present, report enrollment as count of target and calculate the percent to the nearest whole number. In PowerPoint, update the current practice slide with the five-line brief. Preserve the deck's theme and other slides.

    Prompting and safetyClear instructions; evidence before action.

    Core habits
    Where to find agents and skills: open Microsoft 365 Copilot Chat with your ELC work account. Agents & Skills is where you find, create, and manage agents and personal skills. Researcher is a built-in agent for multistep research with cited reports. Exact options depend on tenant settings, rollout, and policy.

    An agent's instructions work like a standing prompt, and a skill is a saved procedure. Both still benefit from the same four parts you used in Part 1. Microsoft prompt guidance

    Goal

    What job should the prompt, skill, or agent do?

    Context

    Who uses it, and why?

    Source

    Which approved information may it use, and what is off limits?

    Expectation

    What format, boundaries, and fallback answer should it follow?

    Build in this order: write a good prompt, turn a repeating prompt into a skill, and build an agent only when a team needs a shared assistant with its own knowledge.
    Which license does this guide assume?▼

    Everyone in this GCCS class has a Microsoft 365 Copilot license. Copilot Chat users without the license can use agents grounded on instructions or the web. Your admin controls what you can create and share, and some options depend on tenant settings and rollout.

    Copilot tips & tricksUseful habits and exercise shortcuts.

    Quick reference
    Ask clarifying questions before Copilot answers▼

    Add "Ask any clarifying questions before responding." when the answer depends on details you might have left out, such as audience, scope, source, format, or dates. It's especially useful when you design a skill or an agent.

    This gives Copilot permission to pause, point out what is unclear, and ask for what it needs instead of silently filling gaps. It can reduce assumptions and rework, but it does not replace checking the source or reviewing the final output.

    Ask any clarifying questions before responding.
    Write descriptions people would actually type▼

    Copilot uses a skill's or agent's description to decide when it fits. Include the words your colleagues use for the job, and say what it doesn't do. A vague description gets picked at the wrong time, or not at all.

    Review this description. List three requests that should trigger it and three that should not, and suggest wording that separates them.
    Keep a small test set for every agent and skill▼

    Save five or six test requests: a normal question, a conflicting source, a missing source, prohibited data, an approval request, and missing input. Rerun them after every change and before you share.
