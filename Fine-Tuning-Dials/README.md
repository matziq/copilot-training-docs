# Fine-Tuning Dials

An interactive control panel of the physical constants of the universe.
Turn a dial away from its real, observed value and see — in plain,
scientifically-grounded language — what kind of universe results: no
stars, all matter crushed into black holes, a cosmos of pure hydrogen, a
universe with no carbon, and so on.

Each of the 14 dials represents one constant from the "fine-tuning of the
universe" argument (Martin Rees's *Just Six Numbers*, Barrow & Tipler's
*The Anthropic Cosmological Principle*, the Hoyle carbon-12 resonance,
Penrose's entropy argument): gravity, the strong and weak nuclear forces,
electromagnetism, the electromagnetic-to-gravity ratio, the cosmological
constant, the matter density parameter, the proton-to-electron mass
ratio, the neutron-proton mass difference, hydrogen-fusion efficiency,
the primordial density-fluctuation amplitude, the number of spatial
dimensions, the initial entropy of the universe, and the carbon-12 Hoyle
resonance.

Turning a knob updates a live "consequence panel" describing the
resulting universe, color-coded from green (matches our universe) through
yellow and orange to red (catastrophic). A "Universe status" bar
aggregates every dial into a single habitability read-out, and a
**Randomize** button rolls the dice on all 14 at once — a quick,
visceral illustration of just how narrow the life-permitting range really
is.

## Tech

Vanilla HTML, CSS, and JavaScript. No build step, no bundler, no npm
dependencies, no framework. ES modules are loaded directly by the
browser. It is a fully installable, offline-capable PWA (manifest +
service worker) and is designed so it can be wrapped for Android with
Capacitor later with **zero code changes** — everything uses relative
paths and `localStorage`, and there is no server-side logic or
CORS-dependent networking anywhere.

```
index.html
manifest.webmanifest
sw.js
css/
  variables.css   design tokens (colors, fonts, spacing, safe-area insets)
  base.css        reset + base element styles
  knob.css        rotary knob styling
  layout.css      app shell, header, status bar, dial-card grid
  dialog.css      native <dialog> "learn more" info sheet
js/
  constants.js    the 14 constants: observed values, units, bands, blurbs
  physics.js      pure value/band/formatting/aggregation helpers
  knob.js         the SVG rotary knob (Pointer Events + keyboard)
  state.js        localStorage persistence
  app.js          DOM wiring, event handling, service worker registration
icons/
  icon.svg, icon-192.png, icon-512.png, icon-512-maskable.png,
  apple-touch-icon.png
```

## Running it locally

No build step is required. Any of the following work:

**Plain static server (recommended, needed for the service worker):**

```powershell
python -m http.server 8080
# then open http://localhost:8080/ in a browser
```

**Or just open the file directly** — `index.html` uses only relative
paths, so double-clicking it (or opening it via `file://`) also works,
though the service worker will not register under `file://` (browsers
require a secure context — `http://localhost` or `https://` — for
service workers).

## Wrapping for Android with Capacitor

This app has no build step of its own, so wrapping it is just a matter of
pointing Capacitor's `webDir` at this folder. From the project root:

1. **Initialize an npm project and install Capacitor:**

   ```powershell
   npm init -y
   npm install @capacitor/core
   npm install -D @capacitor/cli
   ```

2. **Initialize Capacitor**, pointing the web directory at the repo root
   (where `index.html` already lives):

   ```powershell
   npx cap init "Fine-Tuning Dials" "com.example.finetuningdials" --web-dir .
   ```

   This generates a `capacitor.config.json` (or `.ts`) similar to:

   ```json
   {
     "appId": "com.example.finetuningdials",
     "appName": "Fine-Tuning Dials",
     "webDir": ".",
     "bundledWebRuntime": false
   }
   ```

   Adjust `appId` to your own reverse-DNS identifier before publishing.

3. **Add the Android platform:**

   ```powershell
   npm install @capacitor/android
   npx cap add android
   ```

4. **Sync web assets into the native project** (run this again any time
   you change the web app):

   ```powershell
   npx cap sync
   ```

5. **Open the project in Android Studio** to build, run on a device or
   emulator, and eventually generate a signed release build:

   ```powershell
   npx cap open android
   ```

No changes to `index.html`, `css/`, or `js/` are needed for this to work:
every asset path is relative, all persisted state lives in
`localStorage` (which Capacitor's WebView supports natively), and there
are no network calls of any kind for the app to function.

`node_modules/`, `android/`, and `ios/` are excluded via `.gitignore` — the
native projects are regenerated by `cap add` and should not be committed.

## Data & accuracy note

Outcome-band boundaries are illustrative approximations chosen to be
consistent with the cited physics literature, not the result of original
numerical simulation. The qualitative direction and severity of every
described outcome (e.g. the deuteron unbinding if the strong force
weakens by a few percent, or the Hoyle resonance's role in carbon
nucleosynthesis) reflects the real arguments made in the sources above.
This is an educational simulation, not a physics engine.
