2.1 Design AI and agents: agent types, orchestration, and building blocks

Pick the right agent pattern, orchestration mode, and component for a stated requirement.

An architect on this exam is judged on fit. Most wrong answers in Domain 2 are real Microsoft features used in the wrong place. Start every scenario by asking three questions: who or what starts the work (a person, an event, a schedule), how much autonomy is acceptable (answer only, act with approval, act alone), and where the data lives (Dataverse, SharePoint, an external API, a legacy UI).

Agent types and how they start

Prompt-and-response agent reactive

A user asks; the agent answers, usually grounded in knowledge sources. Little or no side effect on systems of record. Examples: an HR policy Q&A agent, a product-spec lookup agent.

Trigger: a user message in a channel (Teams, Microsoft 365 Copilot, web chat).

Task agent acts on request

A user asks the agent to do something: create a case, book time off, update an opportunity. It calls tools, connectors, or flows and returns a result. A human is in the loop for every run.

Trigger: a user message that maps to a tool or topic.

Autonomous agent event-driven

Runs without a person typing. It reacts to events or schedules, plans steps with generative orchestration, and acts within guardrails such as approvals, scoped connections, and instructions.

Trigger: event triggers such as a new email, a new Dataverse row, a file added to SharePoint, or a recurrence schedule.

Design principle

Autonomy is a risk dial, not a feature checkbox. The more autonomous the agent, the more you need least-privilege connections, human approval steps for sensitive actions, telemetry, and clear instructions on what the agent must never do. Autonomous triggers rely on generative orchestration, because the agent must plan without a user utterance to match.

Exam trap

“Process every incoming invoice email overnight with no user involved” is an autonomous agent with an event trigger, not a task agent. “Let a seller ask the agent to log a call” is a task agent. Watch for the word that tells you who initiates.

Copilot Studio topics, system topics, and fallback

A topic is an authored conversation path: trigger, nodes (messages, questions, conditions, tool calls, generative answers), and variables. Use topics where you need deterministic control, such as regulated wording, multi-step data capture, or a guaranteed escalation path.

Conversation StartWhen the agent first engages the userGreeting and capability statement. In Teams it effectively runs once per user, because Teams reuses the conversation ID.
Conversational boostingWhen no authored topic matchesHolds the generative answers node; knowledge added at the agent level is used here. This is the default “answer from knowledge” safety net.
FallbackWhen the agent can’t understand the utterance with enough confidenceRephrase prompts, call an external Q&A service through a flow, or escalate after repeated misses.
EscalateWhen the user asks for a person or a topic redirects to itHand off to a live representative, for example through Dynamics 365 Contact Center.

Remember

System topics can be turned off but not deleted. Customize them only after the end-to-end conversation works. Copilot Studio supports a large but finite number of topics per agent, so offloading thousands of single-turn Q&A pairs to knowledge or an external service through the Fallback topic is a valid architecture.

Standard NLU vs CLU vs generative orchestration

Copilot Studio separates generative orchestration (the default for new agents) from classic orchestration. Classic orchestration offers three language-understanding options: standard NLU, NLU+, and Azure conversational language understanding (CLU).

OptionHow intent is recognizedChoose it whenWatch out for
Generative orchestrationA language model reads topic, tool, knowledge, and agent descriptions, builds a plan, and can chain several in one turnMulti-intent requests, broad scope, autonomous triggers, connected or child agents, automatic slot fillingQuality depends on clear descriptions and instructions; less deterministic; consumes generative capacity

NLU+Enhanced, trained model using larger sets of training phrases and entitiesLarge enterprise agents with many topics and entities that need high accuracy; voice agents benefit from the training dataMore training data to curate and maintain

Exam trap

In classic mode, knowledge is a fallback and tools run only when a topic calls them. In generative mode, the agent can call tools and search knowledge proactively based on their descriptions. If a scenario says “the agent ignores the new tool,” the fix is usually a better name and description (generative) or an explicit call from a topic (classic).

Hybrid pattern

Some regulated teams keep classic orchestration for deterministic routing but put an AI prompt inside Conversational boosting to classify intent and redirect to a topic. This blends predictability with flexible understanding and is a good answer when a scenario demands both.

Agents vs agent flows vs Power Automate cloud flows

Agent

Reasoning and conversation. Uses instructions, knowledge, tools, and topics to decide what to do. Non-deterministic by nature.

Agent flow

A deterministic, step-by-step workflow built and managed in Copilot Studio. Same connector ecosystem as Power Automate, billed with Copilot Studio capacity, and callable by an agent as a tool. Can include AI actions and human approvals.

Power Automate cloud flow

Deterministic automation owned in Power Automate, licensed with Power Automate. Good for existing enterprise automations that an agent should reuse rather than rebuild.

Rule of thumb: let the agent decide what; let a flow guarantee how. Anything that must happen the same way every time, such as posting a journal, writing an audit record, or sending a regulated notice, belongs in a flow the agent calls, not in free-form model output.

Prompt actions (AI Builder prompts)

A prompt is a reusable, parameterized natural-language instruction with typed inputs and an output (text or JSON) that runs on a managed language model. You build prompts in the prompt builder (reachable from AI hub in Power Apps and Power Automate, or from the Tools page in Copilot Studio) and reuse them in:

  • Copilot Studio as a prompt tool the agent or a topic can call.
  • Agent flows and cloud flows as a “Run a prompt” step.
  • Canvas apps as a Power Fx function (call the prompt by name with .Predict()).
  • Dataverse low-code plug-ins for server-side enrichment.

Prompts can be grounded on Dataverse data and can use code interpreter or document inputs, depending on configuration. Choose a prompt when the task is a bounded transformation (classify, extract, summarize, rewrite) that should behave consistently across apps. Admins can turn the AI prompts feature on or off per environment in the Power Platform admin center.

Exam trap

Document Intelligence vs Content Understanding is a favorite distractor pair. Standard invoices at volume with a prebuilt model: Document Intelligence. Contracts that vary wildly, with fields you describe in plain language and want confidence scores for: Content Understanding.

Data processing for AI models and grounding

Pipeline

  1. Ingest from source systems with permissions preserved.
  2. Clean and normalize: remove duplicates, stale versions, boilerplate.
  3. Extract text and structure (Document Intelligence or Content Understanding).
  4. Chunk by semantic boundaries such as headings or sections, with modest overlap.
  5. Embed each chunk with an embedding model.
  6. Index vectors plus keywords and metadata (Azure AI Search).
  7. Retrieve with hybrid search and semantic ranking, filtered by user access.
  8. Refresh on a schedule or change feed.

Architect choices

  • Chunks too large dilute relevance; too small lose context.
  • Metadata (department, region, effective date) enables security trimming and freshness filters.
  • Hybrid (keyword + vector) beats either alone for part numbers, codes, and names.
  • Use the same embedding model at index and query time; changing it means re-indexing.
  • For Copilot Studio, built-in knowledge sources (SharePoint, Dataverse, files, websites, connectors) handle much of this for you; go custom with Azure AI Search when scale, ranking, or control demands it.

2.1 continued: apps, Well-Architected, and Dynamics 365 Copilot design

Embed AI in Power Apps and Dynamics 365 the way the platform expects.

AI components in a Power Apps canvas app

Options

  • Prompts as Power Fx functions for summarize, classify, or extract inside a business process.
  • AI Builder models such as document processing, receipt and business card reading, object detection, and text recognition controls.
  • Copilot control / embedded agent so users can chat with app data or a Copilot Studio agent in context.
  • Copilot-assisted authoring for makers (generate apps, formulas, and screens from natural language).

Design questions

  • Is the AI step a transformation (prompt) or a conversation (agent)?
  • Should a person confirm the AI output before it is saved?
  • Which capacity or credits pay for the calls?
  • Is the feature available in the environment’s region, and is it enabled by admins?

Code-first generative pages and agent feed

Generative pages let a maker describe a page in natural language (optionally with an image) and have the app agent generate React code for a model-driven app page bound to Dataverse tables, connectors, or custom APIs. Generated pages are solution-aware, so they move through ALM with the app. Choose them when a model-driven app needs a modern, custom page faster than hand-coding a component.

Agent feed turns a model-driven app into a supervision surface: agents create actionable tasks that users review, validate, and complete inside the app. Agents are added from the app designer’s Agents tab and must use the Power Apps MCP server to post tasks. Choose it when autonomous agents do work that people must oversee in the same app where they already work.

Volatility warning

Agent feed and parts of generative pages have been in preview with changing prerequisites. On the exam, focus on the purpose (human oversight of agent work; AI-generated pages that stay solution-aware), not on dates or UI steps.

Copilot in Dynamics 365 customer experience and service apps

Business terms

Teach Copilot your vocabulary. In Copilot Studio, open the app’s Copilot agent (for Sales, “Copilot in Dynamics 365 Sales”), then add glossary terms with descriptions and synonyms that map alternative names to table columns. Example: map “deal size” to a custom revenue column on opportunity so sellers can ask in their own words.

Customizations

Extend the in-app Copilot through Copilot Studio: add topics, knowledge sources, prompts, connectors, or plugins; configure which fields feed record summaries and “what’s new” recent-change views (which depend on audit history); and adjust email drafting and case summary settings in app settings.

Connectors for Copilot in Dynamics 365 Sales

Copilot in Sales becomes more useful when sellers can reach data outside Dataverse. Design options include:

  • SharePoint for product brochures, price lists, and pitch decks. Admins can limit Copilot to specific SharePoint folders; results respect each user’s SharePoint permissions; common Office files and PDFs are supported.
  • Microsoft 365 data such as email and meetings for account and opportunity context.
  • Power Platform connectors and Copilot Studio extensions to bring in external CRM, ERP, or partner data on demand.
Prerequisites that show up in scenarios

Data loss prevention policies must allow the connectors Copilot needs. If the region has no local Azure OpenAI endpoint, an admin must consent to cross-geo data movement in the Power Platform admin center. Turning on Copilot happens both at the environment level and in Sales app settings.

Agents integrated with Dynamics 365 Contact Center channels

A Copilot Studio agent can be the first responder on digital messaging and voice channels in Dynamics 365 Contact Center. The maker builds and publishes the agent and connects it to the omnichannel instance; the contact center admin configures workstreams, queues, routing, and phone numbers. When the customer needs a person, the agent escalates and passes the conversation history and context variables, so the representative doesn’t restart the conversation.

Digital channels

Chat, SMS, social, and messaging apps through workstreams. The agent handles self-service and hands off via the Escalate topic.

Voice / IVR

Turn on voice in the agent’s settings. Speech recognition, DTMF, barge-in, and silence handling matter. Real-time voice agents are an option for more natural calls.

Smart escalation

Check representative and queue availability before escalating; offer a callback or continued self-service when wait times are long.

2.2 Design extensibility

Decide how to extend Copilot and agents: configure, connect, or bring your own engine.

Agents in Microsoft 365 Copilot: declarative vs custom engine

Decision rule

Start declarative when the work lives in Microsoft 365 and Copilot’s reasoning is good enough. Move to a custom engine agent only when you need custom orchestration, specific or fine-tuned models, proactive behavior, external channels, or multi-system business rules. Custom engines cost more to build, host, and govern.

Custom models in Microsoft Foundry

Microsoft Foundry hosts the model catalog (Foundry Models), fine-tuning, evaluation, and Foundry Agent Service. Design a custom model only when prompting plus grounding fails a measured quality bar, when you need a consistent domain style or format, or when a smaller fine-tuned model can cut cost and latency at volume. Plan for training data governance, evaluation sets, safety evaluation, and versioned deployments. A model router can send each request to the most suitable model to balance cost and quality.

MCP in Copilot Studio

Model Context Protocol is an open standard that lets an agent discover and call capabilities exposed by a server. Of MCP’s primitives (tools, resources, prompts), Copilot Studio uses tools and resources. When the server adds, changes, or removes a tool, the agent sees the change without the maker redefining each action, which is the key advantage over describing every connector action by hand.

  • Connect an existing server with the MCP onboarding wizard (recommended) or through a custom connector built from an OpenAPI schema.
  • Use Microsoft-provided MCP servers (for example Dataverse, Outlook) where available; Dataverse access through MCP honors Dataverse security roles.
  • Because MCP connections surface as connectors, DLP policies and environment governance still apply.
Exam trap

MCP connects an agent to tools and data. A2A connects an agent to another agent. If the scenario is “delegate the whole subtask to a partner’s agent that has its own reasoning,” think connected agents or A2A, not MCP.

Computer Use in Copilot Studio

Computer Use lets an agent operate websites and Windows desktop apps through a virtual mouse and keyboard, driven by a vision-and-reasoning model. You describe the task in natural language; it adapts to minor UI changes better than recorded selectors. Typical uses: data entry into a legacy system, invoice keying, data extraction from portals without APIs.

Design controls

  • Choose where it runs: a hosted browser or your own registered machines.
  • Restrict allowed websites and apps; enforce HTTPS.
  • Store credentials securely rather than in instructions.
  • Add human review for high-impact steps; test with the built-in test pane.

Trade-offs

  • Billed per step, so long UI journeys get expensive.
  • Slower and less deterministic than an API.
  • On-screen content can carry injected instructions; scope access tightly.
  • Prefer connectors or MCP when an API exists; use Computer Use as the last mile.
Exam trap

Computer Use vs Power Automate desktop flows (RPA): desktop flows replay recorded, deterministic steps and suit stable, high-volume UIs. Computer Use reasons about the screen and tolerates change but costs more per run. If the UI never changes and runs thousands of times a day, recorded RPA is often more cost-effective.

Agent behaviors: reasoning and voice

Deep reasoning

Reasoning models think through complex, multistep problems before answering. In Copilot Studio, you invoke reasoning for specific steps in the agent’s instructions (using the keyword reason). Use it for analysis-heavy tasks, such as comparing contract clauses or root-cause analysis, not for simple lookups, because it adds latency and cost.

Voice

Voice-enabled agents serve phone and IVR scenarios. Design for spoken prompts, DTMF input, barge-in, silence detection, latency, and short responses. Real-time voice agents provide more natural turn-taking. Publish to telephony through Dynamics 365 Contact Center or Azure Communication Services.

Agents in Microsoft 365: Teams and SharePoint

Teams

Agents in personal chat, group chats, channels, and meetings. Users @mention the agent in context. Good for team helpdesks and meeting follow-ups. Publish from Copilot Studio to Teams and Microsoft 365 Copilot.

SharePoint agents

Created directly from a site, library, or selected files. Scoped to that content and to each user’s permissions. Fastest path to a Q&A agent over a curated document set.

Agent Builder in Copilot

Lightweight declarative agents built by information workers. Govern with admin controls in the Microsoft 365 admin center.

Remember

SharePoint grounding never overrides permissions. If users can’t open a file, the agent can’t use it for them. Oversharing is a governance problem to fix in SharePoint (and with Microsoft Purview), not in the agent.

Use what Microsoft already ships before building anything custom.

The “buy before build” instinct is heavily rewarded. When a prebuilt Copilot feature or agent meets the requirement, it is usually the best answer because it is supported, secured, and maintained by Microsoft.

Configure Microsoft 365 Copilot for Sales and for Service

Copilot for Sales

  • Deploy the app to Outlook and Teams through the Microsoft 365 admin center or Teams admin center.
  • Connect to the CRM (Dynamics 365 or Salesforce) and choose which fields and record types appear.
  • Configure email summaries, meeting preparation, and saving activities back to the CRM.
  • Extend with Copilot Studio or connectors for extra data sources.

Copilot for Service

  • Connect to the existing CRM and knowledge sources (for example, knowledge bases and SharePoint).
  • Surface case summaries and drafted replies in Outlook and Teams; save interactions to the CRM.
  • Optionally embed the Copilot experience in a non-Microsoft agent desktop.
  • Govern via the admin experience and the CRM’s own security model.
Exam trap

“Copilot in Dynamics 365 Sales” runs inside the Sales Hub app. “Microsoft 365 Copilot for Sales” brings CRM context into Outlook and Teams and works with Salesforce too. If sellers refuse to leave Outlook, or the CRM isn’t Dynamics 365, pick the Microsoft 365 offering.

Power Platform AI features, including AI hub

AI hub in Power Apps and Power Automate is the starting point for AI Builder capabilities: prompts (with a prompt library of templates by job type and task), prebuilt models (document processing, text recognition, sentiment, and similar), and custom models you train. Pair it with Copilot in Power Apps, Power Automate, and Power Pages for makers, Copilot Studio for agents, and managed environment controls in the Power Platform admin center to govern who can use which AI features.

Finance and operations agent chats with additional knowledge sources

To let users chat with structured finance and operations data, add it as a knowledge source in Copilot Studio. Two patterns:

  • Virtual entities expose finance and operations data live in Dataverse without copying it.
  • Native Dataverse tables populated through dual-write or another sync, then added as knowledge.

Either can ground Copilot for finance and operations apps, custom agents, or Microsoft 365 Copilot agents. Answers respect what each user can access.

Knowledge sources for in-app help and guidance (Finance and SCM)

  1. Open Copilot Studio in the Dataverse environment linked to the finance and operations environment.
  2. Open the agent named Copilot for finance and operations apps.
  3. On the Knowledge tab, upload files (for example PDF or Word) such as internal procedures; they flow to the out-of-box Conversational boosting topic.
  4. For SharePoint or other source types, add your own topic with a generative answers node.
  5. Optionally enable AI general knowledge, which is off by default and raises the risk of incorrect answers.
Watch out

The help-and-guidance topic assumes its knowledge is about using the product. Adding unrelated content can make answers imply false product behavior. Virtual entities are not supported as knowledge for generative help and guidance; use them for data-chat agents instead.

Night-before cheat sheet

The highest-yield pairings for Domain 2.

Agent type by trigger

  • User asks, agent answers: prompt-and-response.
  • User asks, agent acts: task agent.
  • Event or schedule, no user: autonomous agent (generative orchestration).

Orchestration

  • Generative: descriptions drive routing; multi-intent; default.
  • Standard NLU: trigger phrases; simple and deterministic.
  • NLU+: high-accuracy enterprise classic option.
  • CLU: Azure AI Language model; classic only.

Topics

  • Conversational boosting: generative answers when no topic matches.
  • Fallback: low-confidence understanding.
  • Escalate: hand off to a person.
  • System topics: turn off, never delete.

Foundry Tools

  • Standard forms at volume: Document Intelligence.
  • Variable docs, NL schema, confidence: Content Understanding.
  • Retrieval for RAG: Azure AI Search.
  • Prompt injection and harm: Content Safety.

Extensibility

  • Declarative: Copilot’s brain, your instructions, knowledge, actions.
  • Custom engine: your orchestrator and models; proactive; external channels.
  • MCP: tools and resources. A2A/connected agents: other agents.
  • No API: Computer Use (adaptive) or desktop flows (recorded).

Prebuilt first

  • Outlook/Teams sellers or Salesforce: Microsoft 365 Copilot for Sales.
  • In-app CRM Copilot vocabulary: glossary and synonyms in Copilot Studio.
  • F&O data chat: virtual entities or Dataverse tables as knowledge.
  • F&O help: upload files to the Copilot for finance and operations apps agent.
  • Power Platform Well-Architected: five pillars, Experience Optimization (not Cost).
Final reminder

When two answers both work, the exam usually prefers the one that is prebuilt, least privileged, governed by existing controls (DLP, Purview, managed environments), and simplest to maintain through solutions and pipelines.
