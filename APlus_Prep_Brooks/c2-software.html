Software Troubleshooting

Core 2 domain 3.0 is 23% of the exam. Like Core 1’s troubleshooting domain this is scenario-based rather than recall-based — the exam gives you a symptom and asks for the most likely cause or the correct next action, so the way to raise it is doing questions and reading why you were wrong.

Applying the methodology to software.

Use the same six steps, but translate them into account, update, service, and recovery decisions.

Software troubleshooting is still troubleshooting. The exam changes the symptoms, not the order. Read the wording, decide which step the technician is in, and do not jump to a dramatic fix until the methodology allows it.

  1. Identify the problem.
  2. Establish a theory of probable cause.
  3. Test the theory to determine the cause.
  4. Establish a plan of action and implement the solution.
  5. Verify full system functionality and implement preventive measures.
  6. Document findings, actions, and outcomes.
Exam key On Core 2, the "what should the technician do NEXT" questions are answered by this list just as they are on Core 1. The cheapest correct first actions in software scenarios are usually reboot, check for updates, and verify the user’s account and permissions rather than a reinstall.

Identify

Ask what changed, who is affected, when it started, and whether the symptom follows the user or the device.

Test

Use logs, Safe Mode, another profile, another network, or a known-good account to prove the cause before you repair.

Verify

After the fix, prove that the original application, sign-in, update, or security control works for the user.

Windows symptoms and fixes.

Match the symptom to the likely software cause before choosing the least destructive repair.

Windows questions often hide the answer in one phrase: after a driver update, only one user, after sign-in, after Patch Tuesday, or when a service is set to disabled. Those phrases tell you whether you are fixing drivers, profiles, services, updates, or system files.

Symptom Most likely cause Correct action
Blue screen of death (BSOD) and stop codes Kernel-mode driver fault, bad update, memory fault, or storage corruption. The stop code points to the area to test. Record the stop code, disconnect recent devices, boot Safe Mode if needed, roll back the driver or update, then test memory and storage if the crashes continue.
Sluggish performance Startup overload, low RAM, high disk usage, malware, background indexing, or an application consuming CPU. Check Task Manager, disable unnecessary startup apps, scan for malware, install updates, and add resources only when monitoring proves a resource shortage.
Boot problems Damaged boot files, failed update, corrupt driver, disk issue, or incorrect boot order. Use WinRE Startup Repair first, then Safe Mode, System Restore, boot logs, and bootrec only when boot records are implicated.
Frequent shutdowns Thermal protection, power settings, update restarts, bad driver, or malware. Check event logs and temperature, verify power settings, scan for malware, and roll back recent drivers or updates if the timing matches.
Services not starting Service disabled, dependency service stopped, bad credentials, damaged application, or policy restriction. Review Services and Event Viewer, start dependencies, correct the service account, set startup type properly, and reinstall the app only after configuration is ruled out.
Applications crashing Corrupt application files, missing update, incompatible OS version, damaged profile data, or insufficient permissions. Restart the app, check requirements, apply updates, repair or reinstall the application, and test with a new profile if the crash follows one user.
Low memory warnings Too many running apps, memory leak, insufficient RAM, or page file problem. Close or update the offending app, reboot to clear leaks, check Resource Monitor, and add RAM only when usage proves the system is under-provisioned.
USB controller resource warnings Too many devices on one controller, driver conflict, bad hub, or power draw issue. Move devices to another port, remove unneeded devices, update chipset and USB drivers, and use a powered hub when power draw is the issue.
System instability Bad driver, corrupt system files, malware, failed update, or failing storage. Boot Safe Mode to isolate drivers, scan for malware, run sfc /scannow, check disk health, and roll back the last change if it caused the instability.
No OS found Wrong boot device, missing boot files, disconnected or failed drive, or corrupt partition table. Verify boot order and drive detection first, then use WinRE Startup Repair or bootrec. Do not reinstall until the disk and boot files are proven unrecoverable.
Slow profile load Corrupt user profile, huge roaming profile, login script delay, drive mapping timeout, or domain connectivity problem. Test another user, disconnect mapped drives, check domain connectivity, review profile size, and rebuild the Windows profile if the problem follows the user profile.
Time drift Wrong time zone, failed Windows Time service, weak CMOS battery, or blocked NTP communication. Set the correct time zone, restart Windows Time, resync with NTP, and replace the CMOS battery if time is wrong after power loss.

Available remedies and when each is right

Remedy When it is right Exam wording that points to it
Reboot The system or application is frozen, updates just installed, resources are stuck, or the symptom began after a temporary state change. The question asks for the first or simplest step and does not show data loss, security compromise, or failed hardware.
Restart services A Windows feature or application depends on a service that is stopped, disabled, or stuck. Service not starting, print spooler issue, update service stopped, dependency error, or Event Viewer service message.
Uninstall, reinstall, or update applications One application is corrupt, incompatible, missing patches, or broken after an update. Only one app crashes, a version mismatch is named, or repair from Programs and Features is available.
Add resources Monitoring proves CPU, RAM, storage, or network capacity is consistently exhausted. Slow system with Resource Monitor evidence, low memory warnings, or insufficient disk space for updates.
Verify requirements An app will not install, launch, or update on a specific system. Question names minimum RAM, CPU, OS build, disk space, TPM, or architecture requirements.
System File Checker: sfc /scannow Protected Windows system files may be missing or corrupt. System instability, Windows components failing, DLL errors, or unexplained OS behavior after malware or bad shutdown.
Repair Windows Windows installation is damaged but user data and installed apps may be preserved. Startup Repair, in-place repair, or recovery options are available and reimaging is not yet justified.
System Restore A recent driver, application, or configuration change broke the system. The system worked yesterday, a restore point exists, or the symptom began immediately after a change.
Reimage The device must be returned to a known-good corporate baseline or the OS is too compromised to trust. Severe malware, repeated failed repairs, standard corporate image, or many systems need the same clean state.
Roll back updates A Windows update caused a boot, application, driver, or stability problem. Symptom began right after Windows Update or Patch Tuesday and other systems with the same update show the issue.
Roll back device drivers A new or updated driver caused crashes, device failure, or BSODs. The problem appeared after installing a driver or connecting a new device.
Rebuild Windows profiles The issue follows one user profile but not other users on the same device. Slow sign-in, missing desktop, broken Start menu, application settings corrupted, or profile load errors.
Check date and time Authentication, certificates, updates, or cloud sign-in fail because time is wrong. Certificate warnings, update failures, MFA or domain sign-in problems, or time drift after power loss.
Classic trap sfc /scannow checks protected Windows system files. DISM /Online /Cleanup-Image /RestoreHealth repairs the Windows component store that SFC uses as a source. If SFC cannot repair files, DISM is the next tool before running SFC again. Reimaging is correct when trust or baseline matters, such as severe malware or a corporate standard image. It is a lazy answer when a reboot, rollback, repair, or profile rebuild could solve the stated symptom.

Boot and recovery.

Escalate from least destructive to most destructive.

Boot repair questions reward restraint. You always try the least destructive option that could work. A recovery option that preserves user data, profiles, and applications comes before one that removes or replaces them.

  1. Check the simple external causes. Remove bootable USB media, verify boot order, confirm the drive is detected, and undo the most recent physical change.
  2. Use Windows Recovery Environment (WinRE). WinRE is the menu that exposes Startup Repair, System Restore, Command Prompt, uninstall updates, and startup settings.
  3. Run Startup Repair. Choose this when Windows tries to boot but fails because boot files, startup settings, or a failed update are suspected.
  4. Boot Safe Mode. Safe Mode loads minimal drivers and services. If the system works there, suspect third-party drivers, services, startup apps, or malware.
  5. Boot Safe Mode with Networking. Use it when you need network access to download a driver, update signatures, reach documentation, or remove cloud-managed software.
  6. Use Last Known Good when the exam offers it. Treat it as a rollback for a failed driver or configuration after the last successful boot. On modern Windows, System Restore and recovery options are the practical equivalents.
  7. Enable boot logging. Boot logging helps identify the driver or service that loads last before failure.
  8. Disable automatic restart on failure. Use this when the system restarts too quickly to read the BSOD stop code.
  9. Use System Restore. Restore to a point before a bad driver, app, registry, or update change while preserving user data.
  10. Use bootrec /fixmbr. Repair the master boot record when MBR corruption or boot-sector malware is suspected on an MBR disk.
  11. Use bootrec /fixboot. Write a new boot sector when the boot sector is damaged or incompatible.
  12. Use bootrec /rebuildbcd. Rebuild Boot Configuration Data when Windows installations are present but not listed or the BCD store is damaged.
  13. Reset, repair install, or reimage. Use these only after less destructive recovery cannot restore a trusted booting system.
How to read boot scenario wording

If the question says the PC restarted after an update, think uninstall update or System Restore. If it says a new driver was installed, think Safe Mode and driver rollback. If it says no operating system is found but the disk is detected, think Startup Repair or BCD repair. If it says the drive is not detected, do not waste time on Windows tools.

PC security symptoms.

Quarantine suspicious systems before cleaning them.

Security symptoms overlap with ordinary software problems, but the first decision is containment. If the system may be infected, remove it from the network before scanning or browsing for tools.

Symptom What it usually means Right first move
Unable to access the network Malware changed proxy, DNS, firewall, or adapter settings, or the system was blocked by security tools. Quarantine if compromise is possible, then scan and verify IP, DNS, proxy, and firewall settings.
Desktop alerts Potentially unwanted program, fake support tool, or legitimate endpoint protection alert. Quarantine if the alert suggests infection, then run approved anti-malware and review the alert source.
False alerts regarding antivirus protection Rogue security software trying to scare the user into installing or paying. Quarantine, scan with trusted tools, remove the rogue application, and verify real antivirus status.
Altered system files or personal files Malware, ransomware, unauthorized access, or failed sync process. Quarantine immediately, preserve evidence, scan offline if required, and restore from known-good backup only after cleaning.
Unwanted notifications within the OS Browser notification abuse, adware, or unwanted application permissions. Reset browser notification permissions, uninstall the suspect app, and scan for adware.
OS update failures Corrupt update components, malware blocking updates, wrong time, or insufficient disk space. Check date and storage, scan if compromise is suspected, then repair update components or run DISM and SFC.
Browser pop-ups and redirection Adware, malicious extension, abused notifications, compromised browser profile, proxy change, or DNS hijack. Reset browser settings, remove extensions, clear notification permissions, verify DNS and proxy, and scan for malware.
Certificate warnings Wrong date and time, captive portal, proxy inspection, or malicious redirection. Check the certificate and system date first, then verify network and browser settings before entering credentials.
Contain first A machine showing these symptoms gets quarantined before anything else. Remove network access, protect other systems, and then follow the malware process in Core 2 security malware removal.

Mobile OS and application issues.

Fix apps before resetting the phone.

Mobile troubleshooting is usually an escalation path: close the app, clear temporary data, update, reinstall, reset settings, then factory reset only when the device or account cannot be trusted or ordinary fixes fail.

Issue Likely cause Fix
Application fails to launch Corrupt cache, missing permission, outdated app, unsupported OS version, or low storage. Force stop, clear cache, verify permissions and storage, update the app, then reinstall if needed.
Application fails to close or crashes App bug, bad cache, memory pressure, or conflicting update. Force close, reboot, clear cache, update or roll back the app, and reinstall if crashes continue.
Application fails to update Low storage, account problem, restricted network, OS too old, or app store issue. Check storage space, confirm the account, use Wi-Fi, update the OS, then retry the store update.
Slow to respond Too many background apps, low storage, weak battery health, malware, or outdated OS. Close apps, clear cache, free storage, update the OS, scan if available, and soft reset.
OS fails to update Insufficient storage, low battery, unsupported device, poor Wi-Fi, or blocked management profile. Charge the device, connect to reliable Wi-Fi, free storage, verify model support, and check management restrictions.
Battery life issues Background location, push sync, bad app, weak signal, aging battery, or high screen brightness. Review battery usage, restrict or uninstall the bad app, update the OS, reduce radios or brightness, and replace the battery when degraded.
Randomly reboots Bad OS update, overheating, failing battery, malware, or hardware fault. Update the OS, remove recent apps, check temperature and battery health, soft reset, and factory reset only after backup and other fixes fail.
Connectivity issues: Bluetooth, Wi-Fi, NFC, AirDrop Radio disabled, pairing problem, airplane mode, wrong network, permissions, range, or incompatible sharing settings. Toggle the radio, forget and re-pair, verify permissions and discovery settings, reset network settings, and update the OS.
Screen does not autorotate Autorotate lock enabled, app does not support rotation, sensor calibration issue, or case obstruction. Verify the autorotate lock first, test another app, remove the case, reboot, and update the OS.

Mobile security symptoms.

Assume a suspect app or account until proven otherwise.

Mobile compromise often looks like poor performance. The exam expects you to connect ads, traffic, and unexpected behavior to app permissions, sideloading, malicious profiles, or stolen account credentials.

Symptom What it suggests Response
High network traffic Malicious or over-permissioned app, background sync loop, tethering abuse, or compromised account. Review data usage by app, remove the suspect app, check account sessions, update the OS, and run mobile anti-malware if available.
Sluggish response time Resource-heavy app, malware, low storage, or outdated OS. Check battery and storage usage, uninstall suspicious apps, clear cache, update, and scan.
Data-usage limit notification Unexpected background upload or download from an app, sync client, or compromised account. Identify the app using data, restrict background data, uninstall if suspicious, and change passwords if account sync is unknown.
Limited internet connectivity Malicious VPN/profile, DNS change, captive portal, weak signal, or carrier restriction. Check Wi-Fi and carrier status, remove unknown VPN or management profiles, reset network settings, and update.
No internet connectivity Radio disabled, bad profile, malware network block, unpaid carrier service, or failed update. Verify radios and account status, remove suspect profiles, reset network settings, and scan if compromise is possible.
High number of ads Adware, malicious browser notifications, or an app abusing notification permissions. Remove suspicious apps, reset browser settings, revoke notifications, and scan.
Fake security warnings Scareware web page, rogue app, or malicious notification permission. Do not tap the warning, close the page, clear browser data, remove notification permission, and uninstall the source app.
Unexpected application behavior Compromised app, excessive permissions, sideloaded package, or account takeover. Review app permissions, uninstall the suspect app, update the OS, and change the related password.
Leaked personal files or data Compromised cloud account, malicious app permissions, stolen device, or unauthorized backup access. Change passwords, revoke sessions, enable MFA, remove suspect apps, scan, and factory reset with restore from a known-good backup in the worst case.
Mobile fix order For ordinary app problems, use force stop → clear cache → reinstall → update → reset. For security problems, preserve data where required, remove the suspect app, change passwords, update, scan, and use a factory reset only when trust cannot be restored.

The night-before Software Troubleshooting sheet.

Memorize the order, then drill scenarios.

Six methodology steps

  1. Identify the problem.
  2. Establish a theory.
  3. Test the theory.
  4. Plan and implement the fix.
  5. Verify and prevent recurrence.
  6. Document findings, actions, and outcomes.

Recovery ladder

  1. Check boot order and removable media.
  2. WinRE.
  3. Startup Repair.
  4. Safe Mode or Safe Mode with Networking.
  5. Last Known Good when offered.
  6. Boot logging.
  7. Disable automatic restart.
  8. System Restore.
  9. bootrec /fixmbr, /fixboot, /rebuildbcd.
  10. Repair, reset, or reimage.

Driver, corrupt system files, malware, failed update, or storage.

sfc vs dism

sfc /scannow verifies protected system files. DISM repairs the component store that SFC uses. If SFC cannot fix corruption, run DISM, then run SFC again.

Mobile fix order

Use force stop → clear cache → reinstall → update → reset. Factory reset is last because it removes user state and should follow backup and account checks.

Last-minute decision rules

Question wording Best direction Why
Only one user has the problem on a shared PC. Test another profile, then rebuild the damaged profile if needed. The operating system is probably functional; the user profile or permissions are more likely.
Every user has the problem on one PC. Check local services, drivers, updates, application files, and system files. The symptom follows the device, not the account.
Many PCs fail right after the same update. Roll back the update, pause deployment, and document the change. A shared timing clue points to patch impact, not random corruption.
The app will not install or update. Verify requirements, disk space, OS build, account, and permissions. Compatibility and prerequisites come before reinstalling Windows.
The browser shows certificate warnings. Check the date, time, certificate, network, proxy, and DNS settings. Wrong time and redirection can make a valid site look unsafe.
The device is infected or cannot be trusted. Quarantine, preserve what policy requires, clean or reimage, then restore from known-good backup. Containment and trust matter more than convenience.

Least destructive

Reboot, restart a service, update an app, roll back a driver, or restore before rebuilding.

Proof first

Use logs, Resource Monitor, another profile, Safe Mode, and known-good settings to prove your theory.

Trust boundary

When malware, data leakage, or altered files appear, quarantine before scan or repair.

When to stop escalating
  • If the symptom is gone, verify with the user and document the result.
  • If the fix changes security posture, confirm policy and permissions afterward.
  • If the device may be infected, do not reconnect it until cleaning or reimaging is complete.
  • If the data is important, confirm backup status before reset or reimage.
  • If the same symptom repeats on many systems, stop treating it as isolated and look for a shared update, policy, or service.
  • If the symptom follows the account, check identity, permissions, and profile data.
  • If the symptom follows the hardware, check drivers, storage, memory, and local services.
Final exam filter Before picking a destructive answer, ask whether the question gave you evidence that cheaper fixes failed. If not, choose the least destructive action that directly addresses the symptom.
