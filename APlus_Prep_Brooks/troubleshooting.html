Hardware & Network Troubleshooting

This is domain 5.0 and 28% of Core 1 — the single largest domain on the exam, larger than Hardware. It is scenario-based rather than recall-based, so the way to raise the score here is to practice mapping symptom to most likely cause.

The six-step methodology

Answer next-step questions by following the official order.
  1. Identify the problem.

    Gather information from the user, identify user changes, inquire regarding environmental or infrastructure changes, and back up before making changes, if applicable. Do not jump straight to replacement parts when the scenario is still describing discovery.

  2. Establish a theory of probable cause.

    Question the obvious first: power, cables, link lights, paper, toner, brightness, mute, airplane mode, and recent changes. Consider multiple approaches. Divide and conquer by testing at the midpoint, such as local machine versus network path.

  3. Test the theory to determine the cause.

    Run the test that proves or disproves the theory. Once confirmed, determine next steps to resolve the problem. If the theory is not confirmed, re-establish a new theory or escalate when the problem is outside your scope.

  4. Establish a plan of action to resolve the problem and implement the solution.

    Choose the fix, consider risk, schedule downtime when needed, and refer to vendor documentation for guidance. This is where you replace the failed part, change the configuration, clear the jam, or apply the approved patch.

  5. Verify full system functionality and, if applicable, implement preventive measures.

    Prove the system works from the user’s perspective. Then prevent recurrence when possible: update firmware, improve airflow, replace worn rollers, secure cables, document settings, or educate the user.

  6. Document the findings, actions, and outcomes.

    Record the symptom, cause, tests, fix, parts used, configuration changes, and final result. Documentation helps the next technician and is often the final step in next-action questions.

Next means next The exam constantly asks what the technician should do NEXT. The answer is nearly always the next step in this list, not the most technically clever action.
Scenario snippet Correct next step Why
User says the laptop stopped working after moving desks. Identify the problem. Ask about user changes and environmental changes before testing parts.
You know the printer jams, but no one has checked the paper tray. Establish a theory of probable cause. Question the obvious before disassembling the printer.
You think DNS is failing and need proof. Test the theory. Run nslookup or ping a hostname after testing a public IP.
The failed SSD is confirmed and backups exist. Establish and implement a plan. The cause is known, so perform the approved replacement or restore.
The user can print again after you restart the spooler. Verify full functionality. Print a test page and confirm the user workflow, then prevent recurrence.
The fix is complete and the user confirms success. Document findings, actions, and outcomes. Documentation comes after verification.

Motherboard, CPU, RAM, and power symptoms

Match power and POST symptoms to the safest first check.
Electrical safety If you see smoke, smell burning, hear arcing, or see a swollen battery or bulging capacitor, stop, unplug power, remove the battery if it is safe and removable, and do not keep testing by repeatedly powering on the system.
Symptom Most likely cause First thing to check
No power at all Bad outlet, AC adapter, power supply, DC jack, battery, or motherboard power rail Verify outlet, power cable, adapter LED, and known-good power source.
POST beeps Firmware detected hardware fault such as RAM, video, CPU, or board issue Look up the beep pattern in vendor documentation.
POST code on display or board Hardware initialization stopped at a vendor-specific checkpoint Check the motherboard manual or service guide for that code.
No display but fans spin Display output, GPU, RAM, firmware, or monitor input problem Check monitor power/input/cable, then reseat RAM and test external display.
Intermittent shutdown Loose power connection, overheating, failing PSU, failing battery, or motherboard fault Check event timing, temperatures, power connection, and logs.
Sudden shutdown under load Thermal protection or insufficient power delivery Inspect heatsink, fan, vents, thermal paste, and PSU capacity.
System does not boot after RAM upgrade Unsupported RAM, bad module, incorrect seating, or wrong slot population Reseat the memory and test one known-good compatible module.
Continuous reboots Bad update, thermal issue, power problem, RAM fault, or boot configuration loop Boot to recovery or safe mode and check recent changes and temperatures.
Burning smell Electrical short, failed PSU, overheated component, or damaged cable Power off, unplug, and visually inspect before further testing.
Smoke Active electrical failure Disconnect power immediately and do not re-energize until repaired.
Distended or swollen capacitors Failing motherboard or power supply capacitors Inspect the board and replace the affected assembly.
Overheating Blocked airflow, dust, bad fan, poor heatsink contact, or failed thermal compound Check vents, fan operation, heatsink seating, and temperature readings.
Thermal throttling CPU or GPU reduces speed to protect itself from heat Monitor temperatures under load and clean cooling path.
Loud or grinding fan Dust buildup, failing bearing, cable touching blades, or unbalanced fan Inspect and clean the fan; replace it if the bearing grinds.
Clock drift Dead CMOS battery or time synchronization disabled Replace CMOS battery and verify date/time settings.
Losing BIOS settings Dead CMOS battery Replace the CMOS battery, then reconfigure firmware settings.
Inaccurate system date/time CMOS battery, time zone, or NTP sync problem Check firmware clock, OS time zone, and time sync status.
Unexpected shutdowns Thermal, power, battery, OS crash, or failing motherboard Check logs, temperature, PSU output, and whether shutdowns happen under load.

Storage and RAID symptoms

Protect data first, then repair hardware or arrays.

Storage troubleshooting begins with data preservation. If a drive is still readable but showing SMART failure, clicking, corruption, or extended read/write times, the right first answer is often to back up the data immediately before running destructive tests.

Symptom Likely cause First response
LED status indicator is amber or red Drive fault, array fault, or enclosure warning Check vendor meaning for that LED and verify backups before replacement.
Grinding noise Mechanical hard drive failure Back up immediately if possible and replace the drive.
Clicking noise Failing hard drive actuator or head assembly Stop unnecessary writes, back up data, and plan replacement.
Bootable device not found Wrong boot order, disconnected drive, failed drive, damaged boot loader, or missing OS Check firmware boot order and whether the drive is detected.
Data loss Deleted files, failing media, malware, corruption, or accidental formatting Stop writing to the disk and restore from backup or image the drive.
Data corruption Failing storage, unsafe shutdowns, bad RAM, file system damage, or malware Back up readable data, then check SMART and file system health.
RAID failure One or more member disks failed or the controller lost metadata Identify the failed member and follow controller documentation.
SMART failure warning Drive predicts impending failure Back up the data immediately and replace the drive.
Extended read/write times Failing drive, bad sectors, full disk, low memory, or heavy background I/O Check disk health and back up before stress testing.
Drive missing in the OS Loose cable, disabled port, driver issue, failed drive, or uninitialized disk Check BIOS/UEFI detection, cables, Device Manager, and Disk Management.
RAID not found Controller disabled, metadata lost, failed controller, missing member, or changed firmware mode Do not initialize disks; check controller settings and array metadata.

A RAID rebuild copies parity or mirror data onto a replacement drive so the array returns to a redundant state. During a rebuild the array is vulnerable, performance is lower, and another disk failure can cause data loss depending on the RAID level.

RAID not found usually means the controller cannot identify the array metadata or the controller mode changed. Initializing the disks can destroy recovery options, so verify configuration and backups first.

RAID trap RAID is availability, not backup. A rebuild restores redundancy after a disk replacement; it does not recover deleted files or protect against corruption copied across the array.

Display symptoms

Separate input source, cable, backlight, inverter, and panel failures.

Start with the simple chain: power, input source, cable, adapter, brightness, and known-good display. Incorrect data source means the monitor or projector is listening on HDMI 2 while the cable is on HDMI 1, DisplayPort, USB-C, or VGA.

Physical cabling issues cause no signal, flicker, intermittent image, wrong resolution, sparkles, or audio loss over HDMI or DisplayPort. Reseat both ends and test a known-good cable before replacing a display.

Symptom Likely cause Best diagnostic
Incorrect data source Wrong monitor or projector input selected Select the input that matches the connected cable.
Fuzzy image Wrong resolution, analog VGA quality, scaling, or bad cable Set native resolution and test a digital cable.
Dim image Brightness setting, failing backlight, or older CCFL inverter failure Raise brightness and shine a flashlight at the screen.
Flickering Loose cable, failing backlight, refresh mismatch, GPU issue, or power problem Reseat cable and test another display or source.
Artifacts or distortion GPU, video memory, overheating, driver, or panel damage Test external display and update or roll back video driver.
Dead pixels Failed pixels in LCD or OLED panel Use a solid-color test and check warranty threshold.
No audio over HDMI or DisplayPort Wrong playback device, cable issue, adapter limitation, or monitor audio disabled Select the digital display audio device in sound settings.
Incorrect color display Loose analog pins, cable issue, wrong color profile, night light, or panel fault Check cable, color profile, and display settings.
Projector overheats and shuts down Blocked vents, dust, failing fan, or burned-out bulb area overheating Clean filters, check fan, and allow proper cooldown.
Burned-out bulb Projector lamp reached end of life Check lamp hours and replace the lamp module.
Failing panel Damaged LCD matrix, connector, or internal electronics Compare internal and external display behavior.

The flashlight test separates backlight from panel. If you shine a bright flashlight at an apparently black laptop screen and can faintly see the desktop, the panel is drawing the image and the backlight or inverter path is the problem.

Display trap A dark screen is not automatically a bad panel. On older CCFL laptops, a failed inverter can leave a faint image that only appears under a flashlight.

Mobile device symptoms

Treat physical damage and battery swelling as safety-first issues.

Poor or no connectivity can come from airplane mode, disabled Wi-Fi, weak signal, wrong SSID, bad password, captive portal, cellular outage, disabled mobile data, SIM problems, or MDM restrictions. Check radios and signal before resetting the device.

If the screen does not autorotate, check orientation lock first. Then test the accelerometer or gyroscope, update the OS, and inspect for physical or liquid damage.

Physically damaged ports cause intermittent charging, no data transfer, bent pins, loose cable fit, or debris-packed connectors. Do not force a connector; inspect and clean carefully with power removed.

A malfunctioning digitizer causes dead touch zones, phantom touches, or no touch response while the image still displays. A cracked display panel affects image output; a cracked digitizer affects touch input.

Battery symptom Most likely cause Mandatory response
Rapid drain Aging battery, high screen brightness, background apps, weak cellular signal, or sync load Check battery health, app usage, radios, brightness, and sync settings.
Swollen battery Internal battery failure and gas buildup Power down, stop charging, do not puncture, isolate safely, and use approved disposal or recycling.
Overheating High workload, poor ventilation, failing battery, charger issue, or environmental heat Remove case if needed, stop heavy use, check charger, and inspect battery health.
Liquid damage Conductive residue, corrosion, short circuits, or contaminated connectors Power off, do not charge, disconnect power, and follow repair or replacement procedure.
Swollen battery rule Never press, bend, pierce, or heat a swollen lithium battery. The exam answer is safe handling and proper disposal, not continued charging or calibration.

Printer symptoms

Map the defect to the paper path, image path, fuser, or driver.

Printer questions often give the defect and ask for the failed component. Laser printers create, transfer, and fuse toner. Inkjet printers spray ink through printheads. Thermal printers use heat-sensitive media or ribbons. Impact printers strike an ink ribbon.

Defect Most likely cause Component cue

Horizontal lines Dirty printhead, failing drum, damaged transfer roller, or repeated defect interval Drum or printhead
Ghost images Drum not fully cleaned or fuser temperature problem Drum or fuser
Toner not fusing to the paper Fuser not heating or wrong media type Fuser
Faded print Low toner, draft mode, clogged inkjet nozzles, or transfer problem Toner, printhead, or transfer roller
Garbled print Wrong driver, corrupted print job, bad cable, or printer language mismatch Driver or spooler
Double or echo images Ghosting from drum or fuser issue Drum or fuser
Incorrect page orientation Application setting, print driver setting, or tray configuration Driver or application
Multipage misfeed Worn pickup rollers, wrong paper, humidity, or separation pad issue Pickup rollers
Paper not feeding Empty tray, worn pickup rollers, bad tray sensor, or incorrect paper size Pickup rollers or tray
Paper jams Obstruction, worn rollers, wrong media, damaged paper path, or fuser exit problem Rollers, path, or fuser
Creased paper Paper path obstruction, worn rollers, humidity, or fuser roller problem Rollers or fuser
Finishing issues Staple jams, hole punch waste full, misaligned finisher, or unsupported media Finisher assembly
Incorrect chroma display Color calibration, wrong driver, low color toner or ink, or incorrect profile Driver, calibration, or color supplies

Fast printer tells Smears that wipe off point to the fuser. Repeating defects point to a rotating part such as the drum. Feed problems point to pickup rollers. Garbled output usually points to the driver or print language.

Network symptoms

Use a ladder so each failure proves one smaller section of the path.

Intermittent wireless connectivity can be weak signal, roaming between access points, channel congestion, power saving, outdated drivers, or interference from microwaves, cordless phones, Bluetooth, thick walls, and neighboring networks.

Slow network speeds can be duplex mismatch, weak Wi-Fi signal, overloaded access point, bad cable, old standard, congestion, malware, or service provider trouble. Limited connectivity often means the host has a local link but cannot reach DHCP or the gateway correctly.

Jitter is variation in packet delay. It hurts real-time traffic such as voice and video. Poor VoIP quality usually means latency, jitter, packet loss, low bandwidth, or QoS problems.

Port flapping means a switch port repeatedly goes up and down. Suspect a bad cable, failing NIC, speed or duplex issue, bad switch port, or power problem on the endpoint.

High latency is delay. External interference hurts wireless reliability. No connectivity means start at the physical layer and prove each rung upward.

Diagnostic ladder

  1. Check the physical link light.

    No link light proves the problem is before IP: cable, port, NIC, switch, power, or wireless association.

  2. Check IP configuration with ipconfig /all.

    APIPA, a 169.254.x.x address, means no DHCP lease. A 0.0.0.0 address means no link or no usable IP configuration.

  3. Ping loopback with ping 127.0.0.1.

    Failure proves the local TCP/IP stack is broken.

  4. Ping the local IP address.

    Failure proves a local adapter, driver, or binding problem.

  5. Ping the default gateway.

    Failure proves the host cannot reach the local router or VLAN gateway.

  6. Ping a public IP such as 8.8.8.8.

    Gateway succeeds but public IP fails proves a routing, firewall, ISP, or upstream problem.

  7. Ping a hostname.

    Public IP succeeds but hostname fails proves DNS name resolution is the likely issue.

Tool result Conclusion Next focus
ping 127.0.0.1 fails Local TCP/IP stack problem Adapter driver, stack reset, OS repair
ping local IP fails NIC or local binding problem Adapter status and driver
ping gateway fails Local network path problem Switch, Wi-Fi, VLAN, subnet, gateway address
ping 8.8.8.8 fails but gateway works Upstream routing or internet problem Router, firewall, ISP, default route
ping hostname fails but public IP works DNS problem DNS server, suffix, cache, name record
tracert stops at first hop Gateway or upstream path issue Router and ISP path
tracert stops after several hops Remote path or provider routing issue Upstream network, remote firewall, provider status
nslookup fails DNS server or record problem DNS settings and authoritative record
nslookup returns wrong address Incorrect DNS record or cache Record correction and cache flush
netstat shows connection established Local host has an active session to that endpoint Application behavior, firewall policy, or remote service
netstat shows listening port A local service is waiting for connections Service identity and host firewall rule

Safety first 1

Unplug and stop testing if there is smoke, burning smell, arcing, or visible electrical damage.
